# Ручной проход и настройки вне кода

Скрипты ловят шаблоны. Здесь то, что видно только при чтении кода со смыслом, и то,
что вообще лежит за пределами репозитория.

## Часть 1. Дыры, которые видно только по смыслу

Читай не файл целиком, а путь данных: откуда пришло → что проверили → что сделали.

### Права и доступ

- Каждый маршрут, который пишет, меняет или удаляет данные, проверяет, кто пришёл. Ищи маршруты, где проверки нет вовсе.
- После загрузки объекта по идентификатору из запроса сверяется владелец. Отсутствие сверки означает, что чужие данные открываются подстановкой другой цифры в адрес.
- Права берутся из базы по сессии, а не из тела запроса. Поле роли, пришедшее от клиента, доверия не заслуживает.
- Административные маршруты закрыты отдельно, а не только спрятаны из меню.

### Ввод и вывод

- Проверка данных происходит на сервере. Проверка только в браузере обходится одним запросом мимо интерфейса.
- Пользовательский текст, который попадает в HTML, экранируется. Ищи вставку разметки напрямую.
- Загружаемые файлы ограничены по типу и размеру и не сохраняются в общедоступную папку.
- Ответы об ошибках не показывают внутренности: пути на диске, запросы, куски конфигурации.

### Ошибки и состояние

- Обработчик ошибки не проглатывает сбой молча. Пустой блок перехвата означает, что сбой проверки прав выглядит как успех.
- Проверка и действие не разъезжаются во времени: «проверил баланс → списал» в двух отдельных запросах даёт списание дважды при одновременном нажатии.
- Операции с деньгами и счётчиками идут одной транзакцией.

## Часть 2. Мёртвый код, который скрипт не видит

Скрипт проверяет ссылки: кто на кого ссылается. Он найдёт то, что никем не вызывается, и пропустит главный случай — **код вызывается исправно, но делу больше не нужен**. Отличить одно от другого можно только по смыслу, поэтому это твоя часть работы.

### Что искать

**Вторая реализация того же самого.** Две функции считают одно и то же разными способами, два похожих компонента, два места, где формируется одно и то же письмо. Текстом они не совпадают, поэтому поиск по образцу их не берёт. Признак: одинаковые слова в названиях, одинаковые поля на входе. Опасность не в дублировании, а в том, что правку внесут в одну копию: цена поменялась в новом расчёте, а старый где-то ещё вызывается и считает по-прежнему.

**Ветка под флагом, который давно не трогали.** Переключатель функциональности, стоящий в одном положении с момента запуска. Вторая ветка — мёртвая, но выглядит рабочей и попадает под правки. Проверь, откуда флаг берёт значение: если из константы или из настройки, которую никто не меняет, вторая ветка мертва.

**Половина прошлого сравнения вариантов.** Проверяли два оформления или два способа оплаты, один победил, второй остался в коде вместе с логикой выбора.

**Код отключённой интеграции.** Перестали пользоваться сервисом, ключи убрали, а вызовы, обработчики ответов и таблицы под них остались. Особенно смотри обработчики входящих запросов от внешних сервисов: они принимают запросы до сих пор.

**Условие, которое никогда не выполняется.** Проверка на окружение, версию, тип подписки или роль, которой в проекте больше нет. Всё, что внутри — мёртвое.

**Поля, которые пишутся и не читаются.** Значение аккуратно заполняется при каждом сохранении, а обращений на чтение нигде нет. Обратный случай тоже важен: поле читают, но заполнять перестали — тогда там всегда пусто, и это уже ошибка, а не мусор.

**Обработчики без источника.** Подписка на событие, которое больше никто не отправляет; задача по расписанию, снятая с расписания; функция обратного вызова, переставшая передаваться.

### Как отличить мёртвое от живого

Три вопроса подряд, прежде чем записать находку:

1. **Кто это вызывает?** Ищи не только импорт — вызов по имени из настроек, из реестра, из строки в базе, из внешнего сервиса по адресу.
2. **Когда это работало в последний раз?** Помогает `git log` по файлу: правка двухлетней давности рядом с активной областью — сильный признак.
3. **Что сломается, если это убрать?** Не можешь назвать — ставь низкий уровень и пиши, что проверить, вместо утверждения.

### Проверка находок скрипта

У скрипта нет способа узнать про вызовы по имени, поэтому его находки про файлы без ссылок и неиспользуемые экспорты помечены низким уровнем намеренно. Пройди по ним и разберись:

- поищи имя файла и имя экспорта целиком по проекту, включая настройки, файлы сборки и строки;
- у наборов готовых компонентов (shadcn и подобные) неиспользуемая часть — норма: их копируют целиком;
- снятую находку так и запиши: «проверено, зовётся оттуда-то». Это экономит следующему человеку тот же самый час.

### Где мёртвый код превращается в дыру

- Файл без ссылок, который при этом объявляет маршрут — забытая живая дверь. Такие проверяй первыми.
- Функция-заглушка на пути проверки прав опаснее отсутствия функции: код выглядит защищённым, а проверки нет.
- Старая копия файла рядом с рабочим часто содержит версию до того, как в неё добавили проверку прав.
- Отключённая интеграция обычно оставляет за собой обработчик входящих запросов без подписи и проверки.

## Часть 3. Чек-лист вне кода

Это человек проверяет сам — сканер туда не дотянется. Отдай списком в конце отчёта.

### Деньги

- [ ] В консолях платных сервисов выставлен потолок трат
- [ ] Ограничение частоты стоит на пользователя, а не только общее на сервис
- [ ] У обращений к платным моделям задана максимальная длина ответа
- [ ] Настроено оповещение о необычном расходе

### Доступы

- [ ] Все ключи, которые хоть раз попадали в git, перевыпущены
- [ ] Боевые и тестовые ключи — разные
- [ ] Двухфакторная защита включена на хостинге кода, в облаке, на платежах и на домене
- [ ] Права служебных доступов урезаны до необходимого минимума
- [ ] У бывших участников проекта доступов не осталось

### Данные

- [ ] Правила доступа к таблицам включены и проверены — по умолчанию база закрыта
- [ ] Резервные копии делаются автоматически, и восстановление хотя бы раз проверялось на практике
- [ ] База не смотрит портом в интернет
- [ ] Пользователь физически не может открыть данные другого пользователя — проверено вручную с двух аккаунтов

### Снаружи

- [ ] Сайт работает по HTTPS, обычный HTTP на него перенаправляет
- [ ] Файлы `.env`, папка `.git` и резервные копии базы не открываются из браузера по прямой ссылке
- [ ] В журналах нет ключей и токенов

Ноль пропущенных галочек не равно безопасности. Это означает, что типовые способы потерять деньги и данные закрыты.

## Как оформлять свои находки

Каждую находку — со ссылкой `файл:строка` и по шаблону из `severity.md`. Догадку без прочитанной строки оформляй как находку низкого уровня с явной пометкой, что проверить.
