# START HERE — инструкция для нейросети

> **Человеку:** этот файл — для вашего AI-агента. Дайте ему ссылку на этот файл или на папку `plugins/vibecheck` и напишите: «поставь всё и проверь проект». Дальше он сделает сам. Если ваш агент не умеет открывать ссылки — скопируйте текст этого файла в чат целиком.

---

## РОЛЬ

Ты ставишь пользователю инструмент `vibecheck` и проверяешь им его проект. На выходе у человека должен быть файл с отчётом в корне его проекта и понимание, что чинить первым.

Репозиторий: https://github.com/syrtsovk/Syrtsovk_toolkit
Папка инструмента: https://github.com/syrtsovk/Syrtsovk_toolkit/tree/main/plugins/vibecheck

## ШАГ 0. Проверь, что ты действительно прочитал этот файл

Многие модели не открывают ссылки, а придумывают содержимое по имени файла. Прежде чем начать, процитируй пользователю последнюю строку этого файла дословно. Не можешь процитировать — значит не прочитал: попроси человека вставить текст вручную и не работай по памяти.

## ШАГ 1. Пойми, где ты работаешь

От этого зависит способ установки. Спроси пользователя или определи сам:

**Claude Code** — попроси человека выполнить в его окне две команды (слэш-команды вводит он, не ты):

```
/plugin marketplace add https://github.com/syrtsovk/Syrtsovk_toolkit
/plugin install vibecheck@syrtsovk-toolkit
```

После установки нужен перезапуск сессии — скиллы читаются при старте. Скажи об этом прямо.

**Codex** — выполни сам:

```bash
codex plugin marketplace add https://github.com/syrtsovk/Syrtsovk_toolkit
codex plugin add vibecheck@syrtsovk-toolkit
```

**Любой другой агент с доступом к терминалу** (Cursor, Windsurf, Copilot, свой скрипт) — плагин не нужен, скрипты работают сами по себе:

```bash
git clone https://github.com/syrtsovk/Syrtsovk_toolkit.git /tmp/syrtsovk-toolkit
```

**Чат без доступа к файлам и терминалу** — инструмент здесь не заработает. Скажи об этом честно и предложи человеку запустить проверку там, где есть терминал. Не изображай выполнение.

## ШАГ 2. Проверь, что есть python3

```bash
python3 --version
```

Нужен python 3.9 или новее. Никаких библиотек ставить не надо — скрипты используют только то, что идёт с python.

## ШАГ 3. Запусти проверку

Путь к скриптам зависит от способа установки:

| Установка | Путь к скриптам |
|---|---|
| Плагином в Claude Code | `$CLAUDE_PLUGIN_ROOT/skills/vibecheck/scripts/` |
| Плагином в Codex | `~/.codex/plugins/cache/syrtsovk-toolkit/vibecheck/*/skills/vibecheck/scripts/` |
| Клонированием | `/tmp/syrtsovk-toolkit/plugins/vibecheck/skills/vibecheck/scripts/` |

```bash
python3 <путь>/vibecheck.py <путь к проекту пользователя>
```

Это займёт от секунд до минуты. Отчёт сам ляжет файлом `vibecheck-report.md` в корень проверяемого проекта.

Покажи человеку сразу: состояние одной строкой, сколько записей, три самых срочных пункта и **полный путь к файлу отчёта**.

## ШАГ 4. Пройди по коду сам

Программы находят известные ошибки по образцу. Дальше нужна твоя голова — она находит то, что видно только по смыслу.

Когда файлов с кодом меньше трёхсот — иди сразу. Когда больше — сначала построй карту и спроси человека, идти ли вглубь: это десятки минут.

```bash
python3 <путь>/scan_map.py <путь к проекту>
```

Карта делит проект на участки и ставит по важности: оплата, вход и права, данные, выкатка и доступы, потом остальное, в конце тесты и старый код.

Заведи файл `vibecheck-progress.md` в корне проекта и иди по участкам **по одному**, отмечая сделанное сразу:

```markdown
# Обход vibecheck
Участков 12, проверено 3

- [x] src/lib/payments      оплата          9 файлов   — 2 находки
- [x] src/lib/admin-auth    вход и права    7 файлов   — 1 находка
- [ ] src/app/api           приём извне     5 файлов   ← здесь остановились
```

Так обход переживает обрыв разговора: видно, где остановились, и можно продолжить.

**Что искать глазами:**

- маршруты, которые меняют данные без проверки, кто пришёл;
- загрузку объекта по номеру из запроса без сверки владельца;
- проверку данных только в браузере, без проверки на сервере;
- перехват ошибки, который молча её теряет;
- код, который исправно вызывается, но делу больше не нужен: вторая реализация того же самого, ветка под переключателем, который давно в одном положении, код отключённой интеграции, поле, которое заполняется и никем не читается.

**Каждую свою находку доказывай.** Пройди путь целиком: какое предположение делает код → конкретный вход, который его ломает → что получится. Не строится на конкретном примере — находка снимается, это догадка.

Ссылка `файл:строка` обязательна.

**Что не выносить в отчёт:** то, что поймает обычный линтер (форматирование, порядок импортов); вкусовое («читалось бы лучше»); то, что уже закрыто рядом проверкой или очисткой; код, который выглядит подозрительно, а при разборе оказался верным.

Свои находки допиши в `vibecheck-report.md` в разделы по смыслу.

## ШАГ 5. Отдай результат

Скажи человеку:

- состояние одной строкой и три самых срочных пункта;
- где лежит отчёт — полным путём;
- сколько участков прошёл из скольких. Дошёл не до всех — так и напиши, не замалчивай;
- если проход по коду не делался — скажи прямо: «проверено только быстрым сканированием», чтобы человек не считал, что проверено всё.

Покажи отдельно чек-лист того, что сканер увидеть не может и надо проверить руками: лимиты трат в личных кабинетах платных сервисов, двойная защита входа, правила доступа к базе, рабочие резервные копии, права служебных доступов, доступы бывших участников проекта.

## ГРАНИЦЫ — соблюдай их

**Нашёл живой ключ — первой строкой ответа скажи «перевыпусти его сейчас»**, до всех остальных объяснений. Ключ, побывавший в истории проекта, считается скомпрометированным, даже если репозиторий закрытый.

**Значение ключа целиком не показывай никогда** — скрипты уже маскируют, ты тоже маскируй.

**Код не правь.** Аудит и починка — разные работы. Предложи починить и дождись согласия. Пока человек не попросил — меняй только файл отчёта.

**Не объясняй, как использовать найденную дыру.** Формат один: что нашли → чем грозит → как закрыть.

**Не обещай безопасность.** Это поиск известных ошибок, а не проверка на проникновение. Пустой отчёт означает «типовых ошибок не нашли», а не «приложение безопасно». Скорость работы инструмент не измеряет вовсе.

## ЕСЛИ ЧТО-ТО НЕ ПОЛУЧИЛОСЬ

| Что случилось | Что делать |
|---|---|
| `python3: command not found` | Попроси человека поставить python 3 и вернись к шагу 2 |
| Скрипт не найден | Ты в другой папке. Найди её: `find / -name vibecheck.py 2>/dev/null` |
| Плагин не ставится | Работай через клонирование, шаг 1, третий вариант |
| Отчёт лёг не туда | Передай полный путь: `--report /полный/путь/vibecheck-report.md` |
| Находок ноль | Так и скажи. Это бывает на аккуратных проектах и это хорошая новость, а не повод что-то придумывать |

Инструмент бесплатный, лицензия MIT, исходники открыты — их можно прочитать целиком перед запуском, и это правильно делать с любым чужим кодом.
