# /backup: копия ключей от Claude Code на случай, если настройки пропадут

**Зачем.** Всё, что вы настроили в Claude Code, лежит в одной папке `~/.claude`. Чистая установка, смена или угон аккаунта (приходится заводить другой), новый Mac могут оставить вас с пустой папкой или затереть прежнюю. `/backup` складывает копию в ваш приватный GitHub-репозиторий, и восстановление занимает час, а не неделю.

**Чем не является.** Это не копия чатов и не копия того, что хранится на стороне claude.ai (проекты, память в веб-версии). Только файлы с вашего компьютера.

## Железные правила

1. **Значения секретов не печатать**, даже частично. Только файл, строка, тип, длина.
2. **Репозиторий бэкапа только приватный.** Скрипт сам проверяет через `gh`; публичный = стоп (код возврата 4), ничего не пишется.
3. **Никаких `reset --hard`, `push --force`, удалений** в репозитории бэкапа. Отстали от облака: `git merge --ff-only`, не вышло: стоп и показать пользователю.
4. **Находки скана секретов = стоп.** Не коммитить, не пушить, не «подумаешь, наверное, тестовый».

## Шаг 0. Готовность

Конфиг лежит в `~/.claude/skills/backup/config.json` (поле `repo` = путь к клону бэкап-репозитория). Нет конфига или клона: пройти `INSTALL.md`.

```bash
B=$(python3 -c "import json,os;print(os.path.expanduser(json.load(open(os.path.expanduser('~/.claude/skills/backup/config.json')))['repo']))")
git -C "$B" status --short              # должно быть пусто (чужих правок в бэкапе нет)
git -C "$B" fetch -q && git -C "$B" merge --ff-only -q @{u}
```

## Шаг 1. Снимок

```bash
python3 ~/.claude/skills/backup/scripts/backup_snapshot.py --apply
```

Скрипт копирует настройки в клон, заменяет зашитые в скрипты ключи заглушками, собирает список MCP-серверов без ключей, обновляет дату в README, делает `git add` и запускает скан. Печатает два раздела: что изменилось в снимке; какие ваши репозитории не в облаке.

| Код | Что делать |
|---|---|
| 0 | чисто → шаг 3 |
| 3 | снимок не изменился → шаг 4 |
| 2 | подозрения → шаг 2 |
| 1 | находки → шаг 2, стоп |
| 4 | репозиторий публичный → сказать пользователю, как сделать приватным, стоп |

## Шаг 2. Находки скана

Открой каждую строку из вывода (файл и номер строки), значение не цитируй.
- **Ложное** (хэш, ID, пример, `<REDACTED>`): продолжить.
- **Настоящий секрет**: `git -C "$B" restore --staged -- <файл>`, добавь шаблон файла в `extra_excludes` в `config.json`, прогони шаг 1 заново. Скажи пользователю, какой файл и что с ним делать (значение в менеджер паролей).

## Шаг 3. Залить

```bash
git -C "$B" commit -qm "backup: снимок $(date +%F) — <что изменилось, по разделам вывода>"
git -C "$B" push -q
git -C "$B" rev-parse --short HEAD @{u}      # совпадают
```

## Шаг 4. Отчёт (по-русски, простыми словами)

Первые 2-3 предложения без терминов: что теперь в безопасности, что ещё может пропасть. Дальше: **Что сделали · Что получили · Чек-лист ✓/✗**.

- Снимок: сколько изменений, по разделам; хэш коммита.
- **Что пропадёт, если Mac умрёт сейчас**: раздел 2 вывода, первые 10 строк, сначала «НЕТ ОБЛАКА», потом «коммитов только здесь». Не пушить эти репозитории самому, предложить.
- Напомнить: ключи, `.env` и заметки `secret_*` в бэкап не входят намеренно, они должны быть в менеджере паролей.

## Регулярный запуск

Раз в неделю. Варианты описаны в `INSTALL.md` (шаг «Расписание»). Работает только когда Mac включён.

## Восстановление

`RESTORE.md` в репозитории бэкапа: клон → `./install.sh --apply` → ключи по `SECRETS-NEEDED.md`. Установка ничего не удаляет и сохраняет заменяемые файлы в `~/.claude-restore-backup-<дата>/`.
