# Установка backup

> **Эта страница написана для AI-агента.** Если вы человек: отдайте своему агенту (Claude Code или Codex) ссылку на этот файл и скажите «установи». Он сделает всё сам и задаст вам три вопроса. Руками тоже можно, команды ниже работают в терминале.

---

## Агенту: прочитай целиком, потом выполняй

Скилл проверен на **Mac**, в агенте с доступом к файлам (на Linux должен подойти, но автор не проверял). Проверено на двух: **Claude Code** (настройки в `~/.claude`) и **Codex** (настройки в `~/.codex`). Другие инструменты можно добавить в конфиге (шаг 4), но автор их не проверял, и ты должен сказать об этом человеку прямо. В веб-версии Claude.ai и ChatGPT скилл не заработает: там нет доступа к файлам компьютера.

Что получится: папка `backup` в каталоге скиллов твоего агента и **отдельный приватный репозиторий** на GitHub человека, куда складывается копия настроек.

**Главное правило: репозиторий бэкапа создаётся только приватным.** Внутри будут скиллы, правила и память человека. Если репозиторий окажется публичным, остановись и скажи об этом человеку.

---

## Шаг 0. Проверить, что есть чем работать

```bash
git --version && gh --version && python3 --version && rsync --version | head -1
gh auth status
```

- Нет `gh` или не выполнен вход: `brew install gh && gh auth login`. Без входа в GitHub облака не будет, остановись и объясни человеку.
- Нет `git`, `python3` или `rsync`: поставь (`brew install git python rsync`) или скажи человеку.

## Шаг 1. Поставить скилл

Каталог скиллов зависит от агента, в котором ты работаешь:

| Агент | Каталог скиллов |
|---|---|
| Claude Code | `~/.claude/skills` |
| Codex | `~/.codex/skills` |

```bash
SKILLS=~/.claude/skills          # для Codex: ~/.codex/skills
mkdir -p "$SKILLS"
git clone --depth 1 https://github.com/syrtsovk/Syrtsovk_toolkit.git /tmp/syrtsovk-toolkit
cp -R /tmp/syrtsovk-toolkit/skills/backup "$SKILLS/backup"
rm -rf /tmp/syrtsovk-toolkit
ls "$SKILLS/backup"
SK="$SKILLS/backup"
```

Должно быть: `SKILL.md`, `INSTALL.md`, `README.md`, `config.example.json`, `scripts/`, `templates/`. Если человек пользуется обоими агентами, поставь скилл в оба каталога: настройки у них общие, бэкап один.

## Шаг 2. Приватный репозиторий для бэкапа

**Спроси человека (вопрос 1):** «Как назвать репозиторий бэкапа? По умолчанию `ai-backup`.»

```bash
cd ~
gh repo create ai-backup --private --clone      # подставь имя
gh repo view ai-backup --json isPrivate -q .isPrivate     # должно быть true
```

Если `gh repo create` вернул ошибку «already exists»: репозиторий уже есть. Клонируй его (`gh repo clone`) и **проверь приватность** той же командой. Не `true`: стоп.

Клон должен оказаться в `~/ai-backup`. Назвали иначе: запомни путь для шага 4.

## Шаг 3. Положить шаблоны в репозиторий

```bash
S="$SK/templates"
B=~/ai-backup
cp "$S/install.sh" "$S/RESTORE.md" "$S/SECRETS-NEEDED.md" "$S/README.md" "$B/"
cp "$S/gitignore" "$B/.gitignore"
chmod +x "$B/install.sh"
```

В `README.md` бэкап-репозитория поправь первую строку под человека, если нужно. Строку `**Дата снимка:**` не трогай: скрипт обновляет её сам.

## Шаг 4. Настройки

**Спроси человека (вопрос 2):** «Какими ИИ-инструментами вы пользуетесь? Claude Code и Codex я подхвачу сам, если их папки есть на компьютере. Если есть другой, скажите какой.»

**Спроси человека (вопрос 3):** «Где у вас лежат git-репозитории с проектами? (например `~/Projects`). Я покажу в отчёте, какие из них не отправлены в облако и пропадут, если Mac умрёт. И брать ли в бэкап память проектов Claude Code (заметки, которые он накопил про ваши проекты; репозиторий приватный, но там может быть личное)?»

```bash
cp "$SK/config.example.json" "$SK/config.json"
```

Отредактируй `$SK/config.json`:

| Поле | Что вписать |
|---|---|
| `repo` | путь к клону из шага 2, по умолчанию `~/ai-backup` |
| `targets` | `null` = взять Claude Code и Codex, чьи папки существуют; или список `["claude"]`, `["codex"]` |
| `custom_targets` | другие инструменты, см. ниже; обычно пусто |
| `include_memory` | `true` или `false` (память проектов Claude Code) |
| `scan_dirs` | список папок из вопроса 3, например `["~/Projects"]`; `null` = поискать в типовых |
| `extra_excludes` | пока пусто, пригодится, если скан найдёт секрет в файле |

`config.json` не содержит секретов, он попадёт в бэкап вместе со скиллом.

### Другой инструмент (необязательно, автор это не проверял)

Если у человека есть ещё один ИИ-инструмент, настройки которого лежат в папке (например `~/.mytool`):

1. Посмотри её: `ls -A ~/.mytool`. Выбери **только** файлы настроек: файл инструкций, каталог скиллов или правил, команды, хуки.
2. **Не бери** входы в аккаунт (`auth.json`, `credentials`, `token*`), историю чатов и сессии (`sessions`, `history`, `*.sqlite`, `*.jsonl`), кэши и логи.
3. Покажи человеку список и спроси: «Беру вот это, верно?»
4. Файлы настроек, где могут быть ключи (`config.toml`, `mcp.json`), перечисли в `sanitize_files`: в бэкап пойдёт копия `*.sanitized` с заглушками вместо значений. Умеем чистить `.json` и `.toml`.
5. Впиши в `custom_targets`:

```json
"custom_targets": [
  {"name": "mytool", "home": "~/.mytool",
   "items": ["rules", "skills", "AGENTS.md"],
   "sanitize_files": ["config.toml"]}
]
```

Скажи человеку: «Для этого инструмента восстановление не проверялось. Проверьте шаг 8 особенно внимательно.»

## Шаг 5. Первый сухой прогон

```bash
python3 "$SK/scripts/backup_snapshot.py"
```

Ничего не пишет. Покажи человеку вывод: цели, сколько файлов попадёт в снимок, какие репозитории не в облаке. Спроси: «Всё верно, делаем первый бэкап?»

## Шаг 6. Первый бэкап

Выполни протокол из `SKILL.md`: снимок, скан, коммит, пуш. Если скан нашёл секреты, действуй по шагу 2 из `SKILL.md`, не пушь.

Проверка в конце: `git -C ~/ai-backup log --oneline | head -3` показывает коммит, и `git -C ~/ai-backup rev-parse --short HEAD` совпадает с `git -C ~/ai-backup rev-parse --short @{u}`.

## Шаг 7. Расписание (необязательно)

Бэкап полезен, если делается регулярно. Раз в неделю, например в понедельник утром.

- **Приложение Claude (десктоп):** регулярная задача (Scheduled tasks) с промптом `/backup`. Работает, пока Mac включён и приложение открыто.
- **Без приложения:** строка в `crontab -e` вида `0 10 * * 1 cd ~ && claude -p "/backup"` (для Codex своя команда запуска, проверь вручную). Проверь вручную один раз, прежде чем полагаться.

Не получилось: ничего страшного, просто запускайте бэкап руками после больших изменений.

## Шаг 8. Проверить, что восстановление работает

Это самое важное: бэкап, который ни разу не пробовали разворачивать, это надежда, а не бэкап.

```bash
cd ~/ai-backup
TARGET_HOME=/tmp/restore-test ./install.sh --apply
ls -A /tmp/restore-test /tmp/restore-test/.claude
rm -rf /tmp/restore-test
```

Должны появиться папки целей (`.claude`, `.codex`, ...) с `skills/` внутри. Дальше инструкция для настоящего восстановления лежит в `RESTORE.md` бэкап-репозитория.

## Итог для человека (скажи в конце)

- Где скилл: каталог скиллов вашего агента, папка `backup`.
- Где копия: ваш приватный репозиторий (адрес).
- Какие инструменты в бэкапе: перечисли цели.
- Что в неё не попадает: ключи, `.env`, входы в аккаунт, история чатов, то, что хранится на стороне сервисов (claude.ai и подобное).
- Что делать дальше: запускать бэкап раз в неделю; перед сменой аккаунта или переустановкой запустить обязательно.
