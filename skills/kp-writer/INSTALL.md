# Установка kp-writer

> **Эта страница написана для AI-агента.** Если вы человек — отдайте своему агенту
> (Claude Code, Codex, Cursor) ссылку на этот файл и скажите «установи». Он выполнит
> всё сам и задаст вам ровно четыре вопроса в конце.
>
> Если хотите поставить руками — команды ниже работают и в терминале.

---

## Агенту: прочитай целиком, потом выполняй

Скилл работает **только там, где есть файловая система**: Claude Code, Codex, Cursor.
В веб-версии Claude.ai он не заработает - ему нужно читать канон методологии с диска
и писать готовые файлы КП. Если ты в вебе, скажи об этом человеку и остановись.

**Обязательны два шага: первый (файлы) и четвёртый (профиль).** Без файлов скилла нет,
без профиля он не знает, чьё имя ставить в подвал коммерческого предложения и куда
складывать документы. Установка без профиля не считается установкой: она даёт скилл,
который на первом же запросе остановится и начнёт спрашивать.

Шаги 2 и 3 - зависимости. Второй сильно влияет на качество, третий почти ни на что.
**Ни один из них не имеет права остановить установку.** Не встало - скажи человеку
одной строкой, что именно и чем это грозит, и иди дальше.

## Шаг 1. Сам скилл (обязательно)

```bash
mkdir -p ~/.claude/skills
git clone --depth 1 https://github.com/syrtsovk/Syrtsovk_toolkit.git /tmp/syrtsovk-toolkit
cp -R /tmp/syrtsovk-toolkit/skills/kp-writer ~/.claude/skills/kp-writer
cp -R /tmp/syrtsovk-toolkit/skills/humanvoice ~/.claude/skills/humanvoice
rm -rf /tmp/syrtsovk-toolkit
```

**Второй скилл, `humanvoice`, ставится вместе с первым - он лежит в том же репозитории
и копируется той же командой.** Он нужен не для красоты: методология отвечает за то,
**что** сказано в предложении, и совсем ничего не делает с тем, **как** это звучит.
Свежесгенерированный текст выдаёт себя гладкими тройками, причастными хвостами
и оценками вместо фактов. Клиент не назовёт причину, но почувствует, и документ,
безупречный по смыслу, прочтётся как рассылка. kp-writer прогоняет через него каждый
текст перед показом.

Не скопировался - не блокер: kp-writer скажет об этом вслух и почистит текст сам,
но слабее.

Проверка - должно вывести восемь файлов:

```bash
find ~/.claude/skills/kp-writer -type f | sort
```

Ожидается: `SKILL.md` · `INSTALL.md` · `README.md` · три файла в `assets/` · четыре в `references/`.
Плюс отдельная папка `~/.claude/skills/humanvoice/` с `SKILL.md` внутри.
Файлов меньше - копирование не прошло, повтори шаг.

Скилл уже виден Claude Code, но **работать ещё не будет** - ему нужен профиль с шага 4.

## Шаг 2. Канон методологии (сильно влияет на качество)

Скилл написан на методологии Advanced JTBD Ивана Замесина. Без канона он работает,
но честно сообщает об этом первой строкой и держится только на встроенных справочниках.

**Почему это важнее, чем кажется.** Общий JTBD (Кристенсен, Moesta, Ulwick) сидит
в весах языковых моделей сильнее, чем методология Замесина. Без канона текст выходит
складным, уверенным и неверным - и это не видно ни агенту, ни автору, ни клиенту.
Канон нужен именно для того, чтобы поймать эту подмену.

Канон открытый, лицензия CC BY-NC-SA 4.0:

```bash
git clone --depth 1 https://github.com/zamesin/Next-Move-Theory-Canon-and-Skills.git /tmp/nmt-src
mkdir -p ~/.claude/nmt-canon
cp -R /tmp/nmt-src/Next-Move-Theory-Canon/. ~/.claude/nmt-canon/
rm -rf /tmp/nmt-src
```

Проверка - должно вывести список файлов, а не пустоту:

```bash
ls ~/.claude/nmt-canon/Advanced-Jobs-To-Be-Done/
```

Ожидаются в том числе: `ajtbd-key-theses.md`, `behaviour-change.md`, `barrier-removal.md`,
`communication.md`, `b2b.md`, `value-creation.md`.

**Если у человека канон уже стоит в другом месте** - не переустанавливай. Запомни
фактический путь и впиши его в профиль на шаге 4.

**Не получилось** (нет сети, нет git) - скажи человеку: «канон не встал, скилл будет
работать с пометкой "сверки не было"» - и переходи к шагу 3.

## Шаг 3. Плагин ui-ux-pro-max (необязательно)

Нужен ровно для одного: подобрать палитру под отрасль конкретного клиента.
**Рабочая палитра уже зашита в шаблон скилла**, поэтому без плагина всё собирается.

Плагин лежит на гитхабе и ставится через маркетплейс Claude Code. Это делается
**из терминала**, то есть ты можешь поставить его сам, без человека:

```bash
claude plugin marketplace add nextlevelbuilder/ui-ux-pro-max-skill
claude plugin install ui-ux-pro-max@ui-ux-pro-max-skill
```

Проверка - в списке должна появиться строка `ui-ux-pro-max@ui-ux-pro-max-skill`:

```bash
claude plugin list | grep ui-ux
```

То же самое можно набрать внутри Claude Code как `/plugin marketplace add ...`
и `/plugin install ...` - результат одинаковый.

**Плагин появится только после перезапуска Claude Code.** Скажи об этом человеку.

Не встало по любой причине - **пропусти и иди дальше**, на работоспособность скилла
это не влияет: он собирает страницу на палитре из своего шаблона.

## Шаг 4. Профиль - ОБЯЗАТЕЛЬНО, четыре вопроса человеку

Здесь остановись и **спроси**. Это тот шаг, на котором скилл собирается под конкретного
человека: его компания, его контакт, его папки. Пропустить нельзя.

**Отвечать за человека запрещено.** Не выдумывай ни названия компании, ни ссылки на чат,
ни пути к папке - даже если можешь их угадать из окружения. Выдуманный контакт в
коммерческом предложении хуже отсутствующего: документ выглядит нормальным и уходит
клиенту, а связаться по нему нельзя. Человек не отвечает прямо сейчас - оставь заглушки
`ЗАПОЛНИ-` как есть и скажи ему, что до ответов скилл работать не начнёт.

```bash
cp ~/.claude/skills/kp-writer/assets/profile.example.md ~/.claude/skills/kp-writer/profile.md
```

Интервью из двух частей. **Первая обязательна**, без неё скилл не работает.
Вторая необязательна, но каждый ответ в ней - это вопрос, которого больше не будет
ни в одном будущем КП.

### Часть 1 - обязательная, четыре вопроса

1. **Как называется ваша компания и чем она занимается?** Название пойдёт в подвал
   документа, короткое имя - в шапку, дескриптор - строкой рядом.
2. **Какой контакт ставить в кнопку для клиента?** Нужна ссылка на **личный чат**
   (телеграм, вотсап), а не на канал: в канал клиенту некуда написать.
   Почтовые ссылки `mailto:` скилл не использует - они открывают почту только там,
   где назначена почтовая программа, у остальных это мёртвая кнопка.
3. **Куда складывать готовые КП?** Путь к корневой папке, внутри которой скилл
   заведёт папку клиента. Например `~/Documents/Клиенты/`.
4. **Где лежит канон методологии?** Если ставил на шаге 2 - `~/.claude/nmt-canon/`.
   Если канона нет - так и напиши, скилл будет работать с пометкой.

### Часть 2 - что человек продаёт

Скажи ему прямо: «Сейчас задам ещё несколько вопросов про то, что ты продаёшь.
Это разовое. Ответишь - скилл больше никогда не будет переспрашивать, чем ты
занимаешься и почём. Не хочешь сейчас - пропустим, но тогда он спросит это
при каждом предложении».

5. **Что продаёшь и что человек от этого получает?** Про деньги спроси отдельно
   и **не дави на число**: «цена считается под клиента» - полноценный ответ, а не отказ.
   Тогда запиши, как устроена сделка (разово · разово плюс ежемесячно · подписка ·
   за объём) и от чего зависит сумма. Устройство сделки обычно одинаковое, даже
   когда цифра каждый раз разная - вот его и надо запомнить.
6. **Кому обычно продаёшь?** Отрасли, размер компаний, кто принимает решение,
   кто потом пользуется.
7. **Какие кейсы можно показывать?** Формат «было → сделали → стало», с цифрами
   и отраслью. **Это самый ценный ответ во всём профиле:** выдумывать кейсы скиллу
   запрещено, и без них он молча убирает из документа целый блок «результаты
   клиентов» - самое сильное место коммерческого предложения. Кейсов нет -
   так и запиши, скилл поднимет доверие другим способом.
8. **Как обычно продаёшь?** Есть ли пилот и почём, порядок оплаты, гарантии,
   что остаётся у клиента при расставании.
9. **Чего ты НЕ делаешь и не обещаешь?** Список границ. Скилл не впишет
   запрещённое, даже если по логике просится - а просится постоянно.

Ответы на часть 2 не заставляй: человек молчит или говорит «потом» - оставь
эти строки как есть и переходи дальше. Установка на этом не ломается.

Профиль - единственное место, где живут личные данные. В самом скилле их нет.
Если человек будет передавать скилл дальше - `profile.md` надо удалить,
вместо него едет `assets/profile.example.md`.

## Шаг 5. Проверка, что всё встало

Выполни и покажи человеку результат:

```bash
S=~/.claude/skills/kp-writer
OK=1
[ -f "$S/SKILL.md" ] && echo "файлы скилла  : ОК ($(find "$S" -type f | wc -l | tr -d ' ') шт)" || { echo "файлы скилла  : НЕТ - шаг 1 не прошёл"; OK=0; }
[ -f ~/.claude/skills/humanvoice/SKILL.md ] && echo "humanvoice    : ОК" || echo "humanvoice    : нет - текст будет чиститься вручную, слабее" 
if [ -f "$S/profile.md" ]; then
  N=$(grep -c "ЗАПОЛНИ-" "$S/profile.md")
  [ "$N" -eq 0 ] && echo "профиль       : ОК, заполнен" || { echo "профиль       : НЕ ЗАПОЛНЕН - осталось $N заглушек"; OK=0; }
else echo "профиль       : НЕТ - шаг 4 не прошёл"; OK=0; fi
C=$(ls ~/.claude/nmt-canon/Advanced-Jobs-To-Be-Done/*.md 2>/dev/null | wc -l | tr -d ' ')
[ "$C" -gt 0 ] && echo "канон         : ОК ($C файлов)" || echo "канон         : нет - скилл будет работать с пометкой"
ls -d ~/.claude/plugins/cache/ui-ux-pro-max-skill >/dev/null 2>&1 \
  && echo "плагин палитр : есть" || echo "плагин палитр : нет, не страшно"
echo "---"
[ "$OK" -eq 1 ] && echo "УСТАНОВКА ЗАВЕРШЕНА" || echo "УСТАНОВКА НЕ ЗАВЕРШЕНА - см. строки выше"
```

Вывелось «УСТАНОВКА НЕ ЗАВЕРШЕНА» - вернись к тому шагу и доделай. Не сообщай человеку
об успехе, пока не увидишь «УСТАНОВКА ЗАВЕРШЕНА»: отчёт об успехе не является
доказательством успеха.

Дальше скажи человеку буквально это:

> Готово. Позовите `/kp-writer` и опишите клиента: кто он, что у него происходит,
> что предлагаем, за какие деньги. Скилл напишет текст предложения и **остановится**,
> чтобы вы его прочитали. Скажете «давай дизайн» - соберёт из него веб-страницу
> одним файлом: открывается без интернета, пересылается клиенту как есть, печатается.

## Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| Скилл не запускается по `/kp-writer` | папка не в `~/.claude/skills/` или сессия старая | проверь путь, перезапусти Claude Code |
| «Сверки с каноном не было» первой строкой | канона нет по пути из профиля | шаг 2, потом поправь путь в `profile.md` |
| Канон стоит, а скилл его не видит | путь в профиле - симлинк | это нормально: скилл ходит `Read` и `grep -r`, а не `Glob`. Проверь сам путь |
| В подвале КП чужое имя | профиль не заполнен или заполнен неверно | открой `profile.md` и поправь |
| Веб-версия не собирается | агент пытается писать файл целиком | скилл запрещает это прямо; убедись, что читается `references/design-agents.md` |
