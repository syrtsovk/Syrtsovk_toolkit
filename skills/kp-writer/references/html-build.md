# html-build.md — сборка HTML-версии КП

> **Когда открываю:** фаза дизайна, текст КП готов и подтверждён. Здесь лежит всё, что нужно, чтобы собрать из него документ, который клиент откроет и прочитает.
>
> **Собирать с нуля не надо.** Скелет со всеми стилями, токенами обеих тем, печатью и рабочим копированием в буфер - `assets/kp-template.html`. Готовые блоки к нему - `assets/kp-blocks.html`. Этот файл объясняет, **что** из них брать и **почему**; шаблон отвечает на вопрос «как».
>
> **Механика жёсткая: `cp` шаблона, дальше точечные `Edit`.** Файл целиком одним `Write` не выдаётся никогда - на 50-80 КБ это кладёт агента по таймауту без результата. Подробно - `design-agents.md`, раздел «Как именно он собирает».

Материал получен практикой на реальном проекте и на трёх минах, которые там взорвались. Мины описаны первыми — они дороже всего остального, потому что каждая делает документ либо нечитаемым, либо создаёт впечатление сломанного продукта у человека, который решает, платить нам почти миллион или нет.

## Зачем вообще HTML, если markdown уже есть

Markdown — рабочий формат для нас. Клиент его не откроет: у него нет редактора, а если и есть, он увидит решётки и палки таблиц.

HTML решает три вещи, которых нет в тексте:

1. **Данные клиента показываются, а не описываются.** График падения выручки бьёт сильнее таблицы из восьми строк. Мокап будущего экрана бьёт сильнее раздела «что входит».
2. **Документ пересылается одним файлом.** Открывается на телефоне, на маке, в переговорке с проектора, печатается для юриста.
3. **Клиент может собрать своё предложение сам**, если оно модульное. Это переводит разговор с «дорого или нет» на «что взять».

Если предложение простое и одноцветное (одна услуга, одна цена, нет данных клиента) — HTML всё равно делаем, просто без калькулятора и половины блоков. Пустая нарядность хуже строгого текста.

## Три мины. Проверять до выдачи, а не после

### Мина 1. Токен темы как фон блока

**Что произошло.** Ценовой блок получил `background: var(--primary)` и белый текст. В светлой теме `--primary` тёмно-синий, всё читается. В тёмной теме этот же токен переворачивается в почти белый — а текст остался белым. Клиент прислал скриншот, где блок с ценой не читается вообще.

**Почему это класс ошибок, а не случайность.** Токены вроде `--primary`, `--fg`, `--bg` по устройству переворачиваются между темами. Их нельзя брать как фон под фиксированный по цвету текст. Ошибка невидима, пока не переключишь тему, а проверяют обычно только светлую.

**Как правильно.** Отдельная пара токенов, которая остаётся тёмной в обеих темах:

```css
:root{
  --ink:#0E1A2E; --ink2:#123E63;   /* фон тёмных блоков */
  --on-ink:#F2F7FD;                 /* текст на них */
  --on-accent:#fff;                 /* текст на акцентном фоне */
}
@media(prefers-color-scheme:dark){:root:not([data-theme=light]){
  --ink:#0A1626; --ink2:#0E3352;    /* всё ещё тёмный, просто другой оттенок */
  --on-ink:#EAF2FB;
  --on-accent:#042539;              /* на светло-голубом акценте текст ТЁМНЫЙ */
}}
.pbox{background:linear-gradient(135deg,var(--ink),var(--ink2));color:var(--on-ink)}
```

Обрати внимание на `--on-accent`: в тёмной теме акцентный цвет становится светлее, и белый текст на нём перестаёт читаться. Та же мина, второй заход.

**Проверка:** в готовом файле не должно остаться ни одного `color:#fff` и ни одного `rgba(255,255,255`. Ищи grep'ом, глазами не найдёшь.

### Мина 2. Ссылка `mailto:`

**Что произошло.** Кнопка «Отправить выбор» открывала почту через `mailto:`. Проверяющий нажал — не произошло ничего. Причина: `mailto` срабатывает, только если в системе назначена почтовая программа. Кто пользуется почтой в браузере — видит мёртвую кнопку.

**Как правильно.** Кнопка кладёт текст в буфер и показывает подтверждение. Вторая кнопка дополнительно открывает телеграм.

Телеграм **не умеет** подставлять текст в личный чат по ссылке — параметр `?text=` работает только для ботов и для `t.me/share/url`. Поэтому порядок: сначала копируем, потом открываем чат, человек вставляет.

Контакт берётся из `profile.md`. Ссылка обязана вести в **личный чат**: в канале клиенту некуда написать.

```js
function copyText(done){
  function fallback(){                      // file:// и старые браузеры
    var ta=document.createElement('textarea'); ta.value=window.__sel;
    ta.style.position='fixed'; ta.style.opacity='0';
    document.body.appendChild(ta); ta.select();
    var ok=false; try{ ok=document.execCommand('copy'); }catch(e){}
    document.body.removeChild(ta);
    if(ok) done(); else showTextForManualCopy();  // всегда есть третий путь
  }
  if(navigator.clipboard && navigator.clipboard.writeText)
    navigator.clipboard.writeText(window.__sel).then(done, fallback);
  else fallback();
}
```

Третий путь обязателен: при открытии файла с диска буфер часто недоступен. Тогда показываем текст в блоке, чтобы выделить руками.

### Мина 3. Кнопка без объяснения

Живая реплика при проверке: «а что она делает? я нажал и ничего». Даже когда кнопка работает, человек не обязан догадываться, что произойдёт.

Под каждой интерактивной кнопкой — строка, объясняющая результат: «складывает ваш выбор в текст со всеми цифрами и кладёт в буфер обмена». После нажатия — видимое подтверждение, которое держится 3-4 секунды.

## Дизайн-система

Не изобретай палитру. Возьми у скилла `ui-ux-pro-max`:

```bash
python3 ~/.claude/plugins/cache/ui-ux-pro-max-skill/ui-ux-pro-max/*/.claude/skills/ui-ux-pro-max/scripts/search.py \
  "B2B commercial proposal business document data-heavy report professional minimal" --design-system
```

Под коммерческие предложения он выдаёт систему **Trust & Authority** — ту, что применяют в финансовых и корпоративных документах, где решение принимают по цифрам:

| Роль | Светлая | Назначение |
|---|---|---|
| primary | `#0F172A` | заголовки, номера разделов, кнопка «наверх» |
| accent | `#0369A1` | акценты, ссылки, активный раздел |
| background | `#F8FAFC` | фон страницы |
| foreground | `#020617` | основной текст |
| border | `#E2E8F0` | рамки, линии таблиц |
| muted | `#EEF2F7` | шапки таблиц, фон чипов |
| danger | `#DC2626` | отрицательная динамика |
| ok | `#047857` | подтверждения |

Шрифты — **системный стек**, а не Google Fonts: файл должен открываться без интернета.

```css
font-family:-apple-system,BlinkMacSystemFont,"Segoe UI",Roboto,"Helvetica Neue",Arial,sans-serif;
```

## Требования к файлу

- **Один самодостаточный HTML.** Ноль внешних ресурсов: ни шрифтов с CDN, ни библиотек графиков, ни картинок по URL. Графики — только инлайн SVG. Единственная внешняя ссылка, которая допустима, — телеграм в кнопке.
- **Русский язык, без буквы «ё» и без длинного тире.** Так владелец скилла пишет сам в переписке, и документ не должен выпадать из его голоса. Только обычный дефис.
- **Иконки — инлайн SVG, не эмодзи.** Эмодзи выглядят по-разному на разных системах и не подчиняются теме.
- **Таблицы в скролл-контейнере.** Обёртка с `overflow-x:auto`, иначе на телефоне таблица разъезжает всю страницу.
- **Печать.** `@media print`: анимации выключены, элементы с анимированной шириной показаны в конечном состоянии, навигация и кнопки скрыты, тёмные блоки печатаются с фоном через `print-color-adjust:exact`.
- **Уважение к настройкам.** `@media (prefers-reduced-motion: reduce)` — все анимации выключаются, скрытые до появления блоки показываются сразу. Это не вежливость: у части людей анимации вызывают физическое недомогание.
- **Тёмная тема** через `prefers-color-scheme`, проверяется отдельно от светлой (см. мину 1).
- **Описание графиков.** На каждом SVG — `role="img"` и `aria-label` с текстовым пересказом: «выручка падает с 53,3 млн в 3 квартале 2024 до 20,1 млн во 2 квартале 2026».

## Блоки, которые доказали пользу

Порядок примерно соответствует силе воздействия.

**1. Мокап продукта.** Самый ценный блок. Нарисованный на HTML макет будущего экрана с **настоящими данными клиента**: его клиенты по именам, его суммы, его сроки. Человек видит продукт, а не описание продукта. Под мокапом — подпись «оформление рабочее, финальный вид согласуем», чтобы не спорить о цвете кнопок вместо сути.

**2. Визуализация масштаба.** Когда в цифрах есть перекос, показывай его физически: шесть фигурок людей против сетки из 170 точек, где точка равна двадцати клиентам. Читается мгновенно и без подписей. Таблица с теми же числами не даёт этого эффекта.

**3. График динамики.** Инлайн SVG: столбики вырастают волной при появлении в экране, затем проявляются линия второго показателя и подписи значений. Пик и текущее значение выделены цветом, между ними — подпись с процентом падения или роста.

**4. Крупные числовые акценты.** Четыре штуки в шапке, досчитывают до значения при появлении. Это те цифры, которые человек запомнит, даже если дальше не дочитает.

**5. Калькулятор сборки** — если предложение модульное. Чекбоксы с зависимостями: зависимый модуль заблокирован и приглушён, пока не выбран базовый; снятие базового снимает зависимые. Пересчёт цены, ежемесячного платежа, срока и рассрочки на лету.

**Калькулятор обязан заканчиваться кнопками копирования и отправки.** Без них он бесполезен — клиент пощёлкает, а мы не узнаем результат. Прямая обратная связь с практики: «зачем галочки, если я всё равно не увижу, что он прощёлкал». С кнопками работает иначе: либо приходит готовая сборка в телеграм, либо человек приходит на встречу с посчитанной цифрой в голове.

**6. Схема потока** из 4-6 шагов с SVG-иконками: откуда берутся данные, что с ними происходит, где появляется результат.

**7. Таймлайн проекта** по неделям — снимает вопрос «а когда я это увижу».

**8. Сравнение с рыночной альтернативой** горизонтальными полосами: длинная полоса студии против короткой нашей. Работает на блокер «дорого», превращая его в «дёшево относительно чего».

**9. Ценовые блоки на тёмном фоне** — визуально отделяют деньги от остального текста. Через `--ink`/`--on-ink`.

**10. Навигационная оснастка:** полоса прогресса чтения сверху, липкая навигация с подсветкой текущего раздела, кнопка «наверх». Документ на 12 разделов без этого читают по диагонали.

## Чек-лист перед выдачей

Прогоняй скриптом, а не глазами — половина пунктов глазами не ловится.

```bash
F="путь/к/КП.html"
grep -c "ё" "$F"                    # ожидаем 0
grep -c "—" "$F"                    # ожидаем 0
grep -oE '(src|href)="https?://' "$F" | sort -u   # только t.me допустим
grep -c "color:#fff\|rgba(255,255,255" "$F"       # ожидаем 0
grep -c "mailto:" "$F"              # ожидаем 0
python3 -c "h=open('$F',encoding='utf-8').read(); print('скобки', h.count('{')==h.count('}')); print('div', h.count('<div')==h.count('</div>'))"
```

Дальше по списку:

- [ ] все разделы имеют якоря, и они совпадают со ссылками в навигации
- [ ] каждая таблица обёрнута в скролл-контейнер
- [ ] есть `@media print`, `prefers-color-scheme: dark`, `prefers-reduced-motion`
- [ ] на каждом графике `role="img"` и осмысленный `aria-label`
- [ ] все ключевые цифры из markdown-версии присутствуют в HTML (проверить поимённо: суммы, сроки, объёмы)
- [ ] под каждой кнопкой есть строка, объясняющая, что произойдёт
- [ ] тёмная тема проверена отдельно от светлой

**Осторожно с автопроверками на парность тегов:** `<header>` содержит `<head` как префикс, `class="flow reveal"` не находится по `class="flow"`. Дважды получали ложные срабатывания. Если проверка ругается — посмотри глазами, прежде чем чинить.

Браузер для проверки может быть занят сеансом владельца скилла — тогда `chrome-devtools` вернёт ошибку про запущенный профиль. Не пытайся его перехватить: проверь файл статически и попроси открыть и глянуть самому, особенно тёмную тему и интерактив.
