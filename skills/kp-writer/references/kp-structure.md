# Структура КП: фреймворки, блоки, чеклисты

> Методология - только из канона `~/.claude/nmt-canon/`. Блок VETO и запрещённые формулировки - в `SKILL.md`, «Шаг 2». Копирайтерские рамки (PAS, AIDA, StoryBrand, SOAR) - **ВНЕ КАНОНА**: они задают форму документа, но определения работ, ценности, проблем и барьеров из них не берутся.

## Опора структуры: КП - это короткая критическая цепочка работ

`[communication.md §8]`. Канон описывает лендинг как короткую критическую цепочку работ, чьё State B - «достаточно веры и мотивации, чтобы сделать первый шаг». КП работает по той же логике. Канонический порядок блоков:

1. Одна строка: что это + какие Core Jobs выполняем + ценность `[communication.md §5]`
2. Фокусные работы - наши Core Jobs вместе с Big Jobs, которым они служат
3. Контекст и триггер - читатель узнаёт свою ситуацию
4. Ценность по конкретным критериям - насколько энергоэффективнее выполняются работы
5. Как именно выполняются работы - фичи как **доказательство**, а не как сообщение `[communication.md §4]`
6. Проблемы текущего решения - какие проблемы, навязанные работы, риски и разрывы цепочки оно производит
7. Снятие конкретных страхов - названный ожидаемый разрыв и почему он не сработает
8. State B / напоминание про Big Jobs - как выглядит и ощущается результат уровнем выше
9. Активирующее знание + CTA - названный продукт, первый шаг, низкая цена входа

**Порядок - это диагностика, а не украшение.** КП не двигает к следующему шагу - спроси, какой переход не сработал: не узнал контекст · ценность не конкретна · доказательство не привязано к критерию · остался реальный барьер в цепочке · остался активный страх · альтернатива не «отстреляна» · CTA требует слишком много до первого «ага».

## Фреймворки структуры

### Для холодного КП (нет контакта)
Каркас - канонический порядок выше, ужатый до 1-2 страниц. Копирайтерская рамка (**ВНЕ КАНОНА**, PAS + AIDA) для формы:
1. Контекст и триггер - клиент узнает себя
2. Проблемы текущего решения + цена бездействия, конкретные потери. **Только реальные проблемы, вскрываем, не выдумываем** `[behaviour-change.md §9]`
3. Core Job + ценность по критериям клиента
4. Micro Jobs с ценностью каждой
5. Кейс из индустрии получателя
6. CTA с минимальным барьером

### Для теплого КП (после встречи)
Диагностика → Решение → Доказательства:
1. Резюме встречи (Big Job клиента своими словами)
2. State A + триггер - что сломалось или изменилось сейчас; какие работы текущее решение выполняет ниже критериев, с цифрами
3. State B - Jobs + ценность по критериям успеха и их приоритету
4. Как мы это делаем - Micro Jobs с ценностью каждой
5. Объективные барьеры - что реально решено (интеграции, доступы, форматы данных, ИБ). Только правда `[barrier-removal.md §4]`
6. Конкретные страхи - какой разрыв клиент предсказывает и почему он предотвращён / обратим / застрахован `[barrier-removal.md §3]`
7. Переиспользование привычки - в какие работающие ритуалы встраиваемся; какие работы клиента исчезают `[behaviour-change.md §11]`
8. Кейсы - SOAR: Ситуация → Препятствие → Действие → Результат (форма, **ВНЕ КАНОНА**)
9. Цены - пакеты с якорением, расчёт против стоимости альтернативы и бездействия
10. Личные работы ЛПР - безопасность, статус, карьерная история, снятие рутины, вендор на третий год `[b2b.md §6]`
11. CTA - конкретный следующий шаг

### Для горячего КП (согласованы условия)
Фиксация договоренностей:
1. Резюме согласованного решения
2. Точные условия, объем, сроки
3. Стоимость и порядок оплаты
4. SLA и гарантии
5. Следующий шаг (подписание)

## Формулы заголовков

### По AJTBD
- Core Job + Ценность: "Контролируйте качество 100% звонков за 5 минут в день"
- Core Job + Big Job + Ценность: "Контролируйте качество всех звонков и растите продажи - за 5 минут в день"
- Триггер + Core Job: "Когда бизнес растет быстрее контроля - автоматическая аналитика берет это на себя"

### Шаблоны
- "Как [клиент] получает [результат] без [конкретная проблема текущего решения / риск]"
- "Система [результат] для [сегмент] за [срок]"
- "[Число] способов решить [проблема] в [контекст]"
- "Что даст [продукт] вашей команде в первые [срок]"

## Формула оффера

```
Для [сегмент].
Которым нужно [job].
Мы помогаем [результат].
За счет [механизм].
В отличие от [альтернатива].
Подтверждено [proof].
```

## Формула кейса (SOAR)

```
Ситуация: У [клиент] было [контекст].
Препятствие: [конкретная проблема с цифрами].
Действие: Внедрили [механизм] за [срок].
Результат: [метрика] за [период].
```

## Блок снятия страхов - и развилка «барьер или страх»

**Сначала проверь развилку** `[barrier-removal.md §3-4]`. Страх - это предсказание клиента, что что-то сломается. Если предсказание **верное** (интеграции правда нет, SSO правда нет, миграции правда нет) - это не страх, а **объективный барьер**: он снимается разработкой и договорённостями, а успокоительный абзац в КП создаёт ложное обещание и будущую проблему уже против нас. Порядок жёсткий: реальность первая, слова вторые.

Шесть классов барьеров `[barrier-removal.md §5]`: нет предпосылки (доступ, документ, формат данных, бюджетный путь) · неподдерживаемый контекст (их АТС, их отрасль, их регламент) · сломанное звено · провал на передаче между ролями · цикл-возврат на доработку · необратимая потеря.

**Если это действительно страх** - механика такая: назвать конкретный ожидаемый разрыв → показать, почему он предотвращён, поглощён, обратим, застрахован или к нам неприменим.

| Предсказание клиента | Формулировка в КП | Сначала проверь |
|---|---|---|
| "Вдруг надо все менять" | "Работает с вашей текущей инфраструктурой - CRM, ERP, 1С без замены систем" | интеграция реально есть? нет - это барьер, чиним |
| "Вдруг долго внедрять" | "Первые результаты через [срок], не через 6 месяцев" | срок подтверждён на похожем проекте? |
| "Кто-то вообще этим пользуется?" | "[N] компаний с оборотом от [X] используют для ежедневного управления" | цифры и логотипы согласованы к публикации? |
| "Если не подойдет" | "Пилотный период [N] дней на реальных данных вашей компании" | пилот реально обратим, деньги реально возвращаются? |
| "Нужно согласовать с 5 людьми" | "Готовая сводка для каждой роли в вашей команде" | сводка правда приложена? |
| "ИБ не пропустит" | — | почти всегда **барьер**, не страх `[b2b.md §7]`: обещать нельзя, надо чинить |

## Формулы CTA

Правило: один CTA, конкретный, низкофрикционный.

Рабочие формулировки для B2B:
- "Согласовать 30-минутный созвон по деталям внедрения"
- "Подтвердить пилот на [N] дней"
- "Оставить комментарии к предложению до [дата]"
- "Назначить встречу с decision maker"
- "Запустить проект с этапа диагностики"
- "Получите бесплатный анализ [N] звонков"

## Якорение цены

Три способа:
1. Enterprise-пакет сверху → основной вариант выглядит разумным
2. Цена потерь: "Каждый месяц без аналитики стоит вам [X] руб"
3. Стоимость альтернативы: "Нанять аналитика = [X] руб/мес, наше решение = [Y] руб/мес"

## Структура блока цен

```
### Вариант 1: [Название] - [Цена]
[Что входит - 3-5 пунктов]
Для кого: [сегмент/ситуация]

### Вариант 2: [Название] - [Цена] ← рекомендуем
[Что входит - 5-7 пунктов]
Для кого: [сегмент/ситуация]

### Вариант 3: [Название] - [Цена]
[Что входит - 7-10 пунктов]
Для кого: [сегмент/ситуация]
```

Если один пакет - показать ROI-расчет рядом с ценой.

## Master-чеклист

### Перед написанием
- [ ] Определен сегмент (по работам, не по демографии)
- [ ] Известны Core Job + Big Job + Super Job сегмента
- [ ] Известны Micro Jobs
- [ ] Назван триггер: почему клиент оценивает альтернативы именно сейчас `[behaviour-change.md §8]`
- [ ] Определены реальные проблемы текущего решения через цепочку Работа → Решение → Проблема (ничего не выдумано)
- [ ] Барьеры отделены от страхов: что чиним реальностью, что снимаем словами `[barrier-removal.md §3-4]`
- [ ] Понятно, в какие уже работающие ритуалы клиента встраиваемся
- [ ] Есть критерии успеха И их приоритетный порядок - под них выбрана механика `[value-creation.md §11]`
- [ ] Определен тип КП (холодное/теплое/горячее)

### Структура
- [ ] H1 = Core Job + Ценность (НЕ название продукта)
- [ ] Контекст/Триггер - клиент узнает себя
- [ ] Триггер клиента назван (или вслух сказано, что его нет и КП работает на активирующее знание)
- [ ] Проблемы текущего решения - конкретные потери по критериям Big Job, только реальные
- [ ] State B - Jobs + ценность по конкретным критериям результата
- [ ] Объективные барьеры починены в реальности, а не «закрыты» текстом
- [ ] Каждый страх назван конкретно и показано, почему разрыв не случится
- [ ] Привычка переиспользуется: названы работы, которые у клиента исчезают
- [ ] Личные работы ЛПР (не только бизнес-цели) `[b2b.md §5-6]`
- [ ] Фичи стоят как доказательство, а не как сообщение `[communication.md §4]`
- [ ] Кейс в формате SOAR
- [ ] CTA с минимальным барьером
- [ ] Активирующее знание (бенчмарк/аудит)

### Анти-буллшит
- [ ] Нет слов "быстро/качественно/надежно" без конкретики
- [ ] Все цифры конкретные и проверяемые
- [ ] Ценность описана через Jobs, не через фичи
- [ ] Формируем ожидания, которые можно превзойти
- [ ] Коммуникация на языке клиента
- [ ] Нет клише типа "уникальное решение"
