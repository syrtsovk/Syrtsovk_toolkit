# Ручной проход и настройки вне кода

Скрипты ловят шаблоны. Здесь то, что видно только при чтении кода со смыслом, и то,
что вообще лежит за пределами репозитория.

## Часть 1. Твой проход по коду

Читай не файл целиком, а путь данных: откуда пришло → что проверили → что сделали.

### Права и доступ

- Каждый маршрут, который пишет, меняет или удаляет данные, проверяет, кто пришёл. Ищи маршруты, где проверки нет вовсе.
- После загрузки объекта по идентификатору из запроса сверяется владелец. Отсутствие сверки означает, что чужие данные открываются подстановкой другой цифры в адрес.
- Права берутся из базы по сессии, а не из тела запроса. Поле роли, пришедшее от клиента, доверия не заслуживает.
- Административные маршруты закрыты отдельно, а не только спрятаны из меню.

### Ввод и вывод

- Проверка данных происходит на сервере. Проверка только в браузере обходится одним запросом мимо интерфейса.
- Пользовательский текст, который попадает в HTML, экранируется. Ищи вставку разметки напрямую.
- Загружаемые файлы ограничены по типу и размеру и не сохраняются в общедоступную папку.
- Ответы об ошибках не показывают внутренности: пути на диске, запросы, куски конфигурации.

### Ошибки и состояние

- Обработчик ошибки не проглатывает сбой молча. Пустой блок перехвата означает, что сбой проверки прав выглядит как успех.
- Проверка и действие не разъезжаются во времени: «проверил баланс → списал» в двух отдельных запросах даёт списание дважды при одновременном нажатии.
- Операции с деньгами и счётчиками идут одной транзакцией.

### Связь с мёртвым кодом

- Файл-сирота, который при этом регистрирует маршрут — это живая дверь, про которую забыли. Проверь такие в первую очередь.
- Функция-заглушка на пути проверки прав опаснее отсутствия функции: код выглядит защищённым, а проверки нет.
- Старая копия файла рядом с рабочим часто содержит версию до того, как в неё добавили проверку прав.

### Что писать в отчёт

Каждую находку — со ссылкой `файл:строка` и по шаблону из `severity.md`. Догадку без прочитанной строки оформляй как находку низкого уровня с явной пометкой, что проверить.

## Часть 2. Чек-лист вне кода

Это человек проверяет сам — сканер туда не дотянется. Отдай списком в конце отчёта.

### Деньги

- [ ] В консолях платных сервисов выставлен потолок трат
- [ ] Ограничение частоты стоит на пользователя, а не только общее на сервис
- [ ] У обращений к платным моделям задана максимальная длина ответа
- [ ] Настроено оповещение о необычном расходе

### Доступы

- [ ] Все ключи, которые хоть раз попадали в git, перевыпущены
- [ ] Боевые и тестовые ключи — разные
- [ ] Двухфакторная защита включена на хостинге кода, в облаке, на платежах и на домене
- [ ] Права служебных доступов урезаны до необходимого минимума
- [ ] У бывших участников проекта доступов не осталось

### Данные

- [ ] Правила доступа к таблицам включены и проверены — по умолчанию база закрыта
- [ ] Резервные копии делаются автоматически, и восстановление хотя бы раз проверялось на практике
- [ ] База не смотрит портом в интернет
- [ ] Пользователь физически не может открыть данные другого пользователя — проверено вручную с двух аккаунтов

### Снаружи

- [ ] Сайт работает по HTTPS, обычный HTTP на него перенаправляет
- [ ] Файлы `.env`, папка `.git` и резервные копии базы не открываются из браузера по прямой ссылке
- [ ] В журналах нет ключей и токенов

Ноль пропущенных галочек не равно безопасности. Это означает, что типовые способы потерять деньги и данные закрыты.
