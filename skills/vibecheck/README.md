# vibecheck

**Скилл-аудитор проекта. Находит утечки ключей, дыры в безопасности и мёртвый код — и объясняет каждую находку так, чтобы её можно было починить самому.**

---

## Зачем он нужен

Проект, собранный быстро, почти всегда несёт один и тот же набор ошибок: ключ, оставленный прямо в коде «на пять минут»; открытый эндпоинт к платной модели; база с паролем `postgres`; папка файлов, которые давно никто не подключает, но которые всё ещё едут в сборку.

Всё это находят не люди, а боты — они сканируют публичные репозитории и открытые порты круглосуточно. Утёкший ключ обнаруживают за минуты, и счёт за чужую генерацию приходит владельцу.

`vibecheck` проходит по проекту и отдаёт отчёт, где каждая находка отвечает на четыре вопроса:

| Вопрос | Что в отчёте |
|---|---|
| Насколько срочно | уровень: критично / высокий / средний / низкий |
| Что нашли | файл, строка, замаскированное значение |
| Почему это опасно | механика вреда простым языком, без терминов |
| Как исправить | конкретные шаги, командой если она есть |

Читаешь сверху вниз и чинишь.

---

## Как устроен

Две части, и они не заменяют друг друга.

**Скрипты** — чистый python3 без единой зависимости. Дают одинаковый результат при каждом прогоне и работают, даже если модель не подключена вовсе:

- `scan_security.py` — ключи 15 сервисов, `.env` в git, платные API из браузера, секреты в публичных переменных, склейка SQL и небезопасные вызовы Prisma, вставка данных как разметки (XSS), `alg: none` в токенах, отключённая проверка сертификата, слабые хеши паролей, сборка команд оболочки из переменных, обход пути к файлу, роль с клиента, молча проглоченные ошибки, отсутствие лимита частоты на входе, эндпоинт к платной модели без авторизации, пароли по умолчанию и проброшенные порты базы, открытые правила Firebase, секреты в логах и в образе контейнера, уязвимые зависимости через `npm audit`.
- `scan_dead.py` — файлы, на которые никто не ссылается, неиспользуемые экспорты, забытые эндпоинты (объявлены, но обращений не видно — это ещё и дыра), копии-дубли (`_old`, `_v2`, `.bak`), функции-заглушки, код после `return`, закомментированные блоки, оставленный отладочный вывод, раздутые файлы, незакрытые `TODO`, неиспользуемые зависимости.

**Модель поверх** — то, что регулярным выражением не поймать: маршруты без проверки прав, отсутствие сверки владельца объекта, валидация только в браузере, проглоченные ошибки. Плюс чек-лист того, что вообще лежит вне репозитория: лимиты трат в консолях, двухфакторная защита, правила доступа к базе, бэкапы, права служебных доступов.

## Как пользоваться

Скажи Клоду:

> Проверь мой проект по vibecheck

Или запусти скрипты руками, вообще без модели:

```bash
python3 skills/vibecheck/scripts/scan_security.py /путь/к/проекту --report security.md
python3 skills/vibecheck/scripts/scan_dead.py /путь/к/проекту --report dead.md
```

На выходе — `vibecheck-report.md` в корне проекта, а в чат приходит главная цифра и тройка «чини прямо сейчас».

## Чего он не делает

Ничего не меняет в проекте: только читает и пишет один файл отчёта. Значение ключа целиком не печатает нигде — ни в чате, ни в отчёте. Способы использовать найденную дыру не описывает: формат один — что нашли, чем грозит, как закрыть.

Это поиск типовых ошибок, а не проверка на проникновение. Пустой отчёт означает «шаблонных дыр не нашли», а не «приложение безопасно»: логику прав внутри приложения, настройки в облачных консолях и инфраструктуру проверяет человек. Для проекта, где ходят деньги или персональные данные, стоит позвать живого специалиста хотя бы раз.

Часть находок — подсказки, а не приговор. Файл без ссылок может дёргаться по имени из конфига, подстановка в запрос может оказаться безопасной. Такое помечено средним или низким уровнем с пометкой, что посмотреть глазами.

## Установка

### Claude Code (CLI)

```bash
git clone https://github.com/syrtsovk/Syrtsovk_toolkit.git ~/syrtsovk-toolkit
mkdir -p ~/.claude/skills
ln -s ~/syrtsovk-toolkit/skills/vibecheck ~/.claude/skills/vibecheck
```

Для одного проекта — положи папку в `<project>/.claude/skills/` вместо `~/.claude/skills/`.

### Claude.ai (web / desktop)

Заархивируй папку `skills/vibecheck` в ZIP и загрузи: **Настройки → Возможности → Skills**. Нужно включённое выполнение кода — скрипты запускаются в песочнице.

---

## Нашёлся живой ключ. Что делать

1. **Перевыпустить прямо сейчас** в консоли сервиса. Если ключ был в git — он скомпрометирован, даже в приватном репозитории.
2. Убрать из кода, положить в `.env`, а `.env` — в `.gitignore`.
3. Историю чистит `git filter-repo`, но пункт 1 обязателен в любом случае.

## Ложное срабатывание?

Заведи issue с фрагментом строки, на которую сработало (**без реального ключа**). Паттерны живут в начале `scan_security.py` — списки `SECRETS` и `CODE_RULES`, добавить свой можно одной строкой.
