# pluginmaker `v1.0`

**Скилл, который делает скиллы. Задаёшь 4-6 вопросов — на выходе готовая папка скилла для Claude Code.**

> Этот README — витрина для GitHub. Claude в работе читает только `SKILL.md`.

---

## Зачем он нужен

У тебя есть повторяющаяся работа — разбор конкурентов, оформление договоров, ревью текстов. Хочется завернуть её в скилл, чтобы Claude делал её одинаково хорошо каждый раз. Но написать `SKILL.md` с нуля тяжело: непонятно, каким должно быть описание, чтобы скилл срабатывал вовремя и молчал, когда не надо; что класть в тело, а что выносить в `references/`.

`pluginmaker` берёт это на себя. Ты говоришь идею человеческими словами — он проводит короткое интервью, подбирает каркас, пишет файлы и сам же их проверяет.

---

## Как это выглядит

```
Ты:      сделай скилл, который разбирает отзывы клиентов на боли
Claude:  [4-6 вопросов через выбор вариантов — тип работы, откуда данные,
          когда срабатывать, когда молчать]
         ↓
         скилл собран, проверен, положен в ~/.claude/skills/pain-extractor/
```

Внутри — 5 фаз:

| Фаза | Что происходит |
|------|----------------|
| **1. Интервью** | 4-6 вопросов с готовыми вариантами ответа. Минимум 3, максимум 6 — если первый ответ подробный, лишнее не спрашивает |
| **2. Выбор каркаса** | Определяет тип скилла из шести и берёт под него шаблон |
| **3. Генерация** | Пишет `SKILL.md`, тест-кейсы и файл с историей решений |
| **4. Проверка** | Три проверяющих работают параллельно: линтер, тестер срабатываний, аудитор качества |
| **5. Деплой** | Спрашивает, куда положить, и кладёт |

---

## Шесть типов скиллов

| Тип | Когда берётся |
|-----|---------------|
| `research-agent` | Поиск → синтез → отчёт со ссылками |
| `code-reviewer` | Ревью кода: баги, безопасность, стиль |
| `workflow-orchestrator` | Многошаговый процесс с состоянием между шагами |
| `doc-generator` | README, документация, структурированные тексты |
| `knowledge-curator` | Ответы по своей базе — vault, вики, заметки |
| `simple-automation` | Один триггер → одно действие |

---

## Проверка в три уровня

Сгенерированный скилл не отдаётся «как есть» — он проходит три независимых проверки:

- **Линтер** — 15 механических правил: формат фронтматтера, структура файлов, отсутствие путей вроде `/Users/имя/`. Без участия модели, работает за секунды
- **Тестер срабатываний** — придумывает 5 запросов, где скилл обязан включиться, и 5, где обязан промолчать. Гоняет их по описанию. Точность ниже 80% — описание переписывается
- **Аудитор качества** — читает готовый `SKILL.md` против 15 правил: нет ли противоречий, не раздуто ли тело, нет ли пустых понтов вроде «ты сеньор с 12 годами опыта»

Вердикт — `PASS`, `PASS-with-warnings` или `FAIL`. При `FAIL` — один заход на исправление, потом решение остаётся за тобой.

---

## Что он не делает

- **Не решает твою задачу.** Просишь скилл для анализа конкурентов — получаешь скилл, а не анализ
- **Не правит существующие скиллы.** Для мелких правок проще открыть файл и поменять руками
- **Не делает промпты для GPTs / Gemini Gems.** Это к [`promptmaker`](../promptmaker/)
- **Не собирает полный плагин** с `marketplace.json` — пока только один скилл

## Установка

```bash
git clone https://github.com/syrtsovk/Syrtsovk_toolkit.git ~/syrtsovk-toolkit
mkdir -p ~/.claude/skills
ln -s ~/syrtsovk-toolkit/skills/pluginmaker ~/.claude/skills/pluginmaker
```

Проверить — открой Claude Code и напиши: «сделай скилл, который …». Скилл подхватится сам.

Подробнее про способы установки (Claude.ai, API) — в [корневом README](../../README.md#установка).
